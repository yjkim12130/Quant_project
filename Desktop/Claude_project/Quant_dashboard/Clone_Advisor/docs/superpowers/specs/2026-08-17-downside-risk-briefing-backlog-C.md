# [백로그] Family C — 미국 증시 하방 위험 [변화] 브리핑

- **상태**: 미착수 — 착수 전 별도 브레인스토밍 세션 1회 필요(이 문서는 스펙이 아니라 잊지 않기 위한 착수 전 메모)
- **참고**: [[project-daily-market-dashboard]] Family C, 예시 이미지 2개 인스턴스 확인(위험등급 9.2/10, 9.7/10)

## 알려진 것

- 헤더에 위험등급 X/10 게이지(VERY HIGH 등 라벨) + 직전 대비 변화(유지/악화/완화).
- 전염 경로(Contagion Path) 다이어그램: 예) 호르무즈 봉쇄 장기화 → 유가·인플레 상방압력 → Fed 재매파 위험 → 위험자산 조정.
- 주요 시장 지표(유가/정제마진/미 국채금리 2·10·30Y/주요지수/엔화달러/신용스프레드 HY OAS·LQD OAS).
- 위험 신호 변화 추적 표(직전→현재, 변화량, 판정 화살표, 다음 확인 조건).
- 24~72시간 체크포인트, 완화조건 vs 악화조건, BULL/BASE/BEAR 시나리오, OODA 프레임(Observe/Orient/Decide/Act).
- **정기 발행이 아니라 이벤트 트리거형으로 추정** — "신규 위험 신호만 반영" 문구가 헤더에 명시됨.

## 착수 전 확인해야 할 핵심 질문

1. **위험등급 산출 방법론**: 9.2/10 같은 점수를 어떤 입력(Brent·10Y·HY OAS·VIX·지정학 이벤트 등)을 어떻게 가중합성해서 낼지 — 이게 이 템플릿의 핵심이자 가장 위험한 부분(대충 만들면 그럴듯해 보이기만 하고 틀린 숫자가 나올 수 있음). 사용자가 실제로 신뢰할 만한 산식이 있는지, 아니면 새로 설계해야 하는지 확인 필요.
2. **트리거 정의**: "새 위험 신호 발생"을 코드가 어떻게 감지할까? (예: 특정 지표가 임계값을 넘으면 자동 트리거? 사용자가 뉴스를 보고 수동으로 "지금 만들어줘" 요청하는 온디맨드? 둘 다 지원?)
3. **크레딧 스프레드(HY OAS/LQD OAS) 데이터 소스**: yfinance로는 못 구함 — FRED API(무료, 시리즈 ID 있음) 등 신규 소스 필요.
4. **신용/유가/정제마진 등 신규 지표**를 Family A의 Tech Dashboard와 통합할지, 완전히 별도 데이터 파이프라인으로 둘지.

## 재사용 가능성

- Family A의 `impact_rules.json` 드라이버 임계값 패턴을 위험등급 서브스코어 계산에 참고 가능.
- 시나리오(BULL/BASE/BEAR) 생성 로직은 Family A `generate_scenarios()`와 구조적으로 유사 — 다만 입력 지표군이 다름.
