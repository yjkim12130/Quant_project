# ManageStock 설계 스펙 v1

- 작성일: 2026-08-16
- 상태: 브레인스토밍 완료, 사용자 검토 대기

## 1. 개요

ManageStock은 개인 투자자가 보유 중인 주식·ETF를 카테고리별로 분류해 포트폴리오 비중과 수익률을 시각화하는 개인용 Streamlit 대시보드다. 기존 Quant_dashboard, Quant_realestate, Quant_lotto와 동일한 스택(Python + Streamlit, 로컬 실행)을 따르는 독립 프로젝트다.

### 목표 (v1 범위)
- 보유 종목(평단가·수량·카테고리·베타)을 UI에서 직접 입력하고, 세션 종료 후에도 계속 유지
- 카테고리별 비중·수익률과 종목 상세 내역을 동시에 시각화
- 신규 종목 매수 시 카테고리·베타만 설정하면 자동으로 대시보드에 반영
- 미국(USD)·한국(KRW) 혼합 자산을 원화 기준으로 합산 표시, 현재 환율 상시 노출
- 일별 자산 스냅샷을 누적해 총자산 추이 표시

### 비목표 (v1 범위 밖)
- 증권사 API 자동 연동(잔고 자동 조회) — 수동 입력만 지원
- 진짜 실시간(초단위) 시세 — 새로고침 시점 지연 시세만 지원
- 환차익/주가수익 분리 표시 — 매입 시점 환율을 기록하지 않기로 결정했으므로 미지원
- 배당금 추적, 다중 포트폴리오(복수 계좌) 관리
- 베타값을 활용한 리스크 조정 노출도 계산 — 베타는 표시 전용

## 2. 아키텍처 (파일 구조)

```
ManageStock/
  app.py                  # Streamlit 진입점, 탭 UI (Tab1: 포트폴리오 대시보드, Tab2: 종목 관리)
  portfolio.py             # 순수 계산 함수 (평가금액/매입금액/수익률/카테고리 집계) — pytest 대상
  data_io.py                # holdings.csv 읽기/쓰기, history.csv append
  market_data.py             # yfinance 시세+환율(USDKRW=X) 조회, st.cache_data 캐시
  categories.py               # 기본 6개 카테고리 상수 + 이름→티커 프리셋 딕셔너리
  data/holdings.csv           # 보유 종목 마스터 (영속, 개인 자산 정보이므로 .gitignore 대상)
  data/history.csv            # 일별 자산 스냅샷 누적 (마찬가지로 .gitignore 대상)
  tests/test_portfolio.py
  .streamlit/config.toml       # port = 8503
  run_app.bat                   # 실행 스크립트
```

계산 로직(`portfolio.py`)을 UI(`app.py`)와 데이터 접근(`data_io.py`, `market_data.py`)에서 분리해, 계산 정확성은 pytest로 독립 검증하고 UI는 그 결과를 그리기만 하도록 한다.

포트는 8503으로 고정한다(8501=Quant_dashboard, 8502=Quant_realestate가 이미 사용 중이라 충돌 방지).

## 3. 데이터 모델

### `data/holdings.csv` (보유 종목 마스터)
| 컬럼 | 설명 |
|---|---|
| `ticker` | 시세 조회용 티커 (예: `005930.KS`, `QQQ`) |
| `name` | 표시용 종목명 (자유 텍스트, 프리셋 유무와 무관) |
| `category` | 카테고리 (기본 6개 중 하나 또는 사용자 추가값) |
| `currency` | `KRW` 또는 `USD`. 티커의 `.KS`/`.KQ` 접미사로 자동 판별하되 수동 override 가능 |
| `quantity` | 보유 수량 |
| `avg_price` | 평단가 (해당 종목 통화 기준) |
| `beta` | 레버리지 배수 (기본값 1.0, 표시 전용) |

### `data/history.csv` (일별 자산 스냅샷, long format)
| 컬럼 | 설명 |
|---|---|
| `date` | 스냅샷 날짜 |
| `category` | 카테고리명, 전체 합계는 `TOTAL`로 별도 기록 |
| `value_krw` | 해당 카테고리(또는 전체)의 원화환산 평가금액 |

long format을 택한 이유는 카테고리가 사용자에 의해 자유롭게 추가되므로, wide format(카테고리별 컬럼)으로 두면 신규 카테고리 추가 시마다 스키마 변경이 필요해지는 문제를 피하기 위함이다.

## 4. 계산 로직

USD 보유분의 매입 시점 환율을 기록하지 않기로 했으므로, 매입금액과 평가금액을 원화로 환산할 때 **오늘 환율을 양쪽에 동일하게 적용**한다. 이렇게 하면 환율이 수익률 계산의 분자·분모에서 상쇄되어 결과적으로 달러 기준 가격변동률과 동일한 수익률이 나오고, 원화 손익금 자체는 항상 "오늘 환율" 기준으로 표시된다. 별도의 환율 이력 저장이 필요 없다.

- 종목별 평가금액(KRW) = `quantity × current_price × (USD면 오늘 환율, KRW면 1)`
- 종목별 매입금액(KRW) = `quantity × avg_price × (USD면 오늘 환율, KRW면 1)`
- 종목별 수익률(%) = `current_price / avg_price - 1`
- 카테고리별 비중 = `해당 카테고리 평가금액 합 / 전체 평가금액 합`
- 카테고리별 수익률 = `해당 카테고리 평가금액 합 / 해당 카테고리 매입금액 합 - 1` (금액가중, 단순 평균 아님)
- 전체 수익률 = `전체 평가금액 합 / 전체 매입금액 합 - 1`
- 전체 손익금(KRW) = `전체 평가금액 합 - 전체 매입금액 합`

## 5. UI 구성

### Tab1 "포트폴리오 대시보드"
1. 상단 메트릭: 총평가금액(KRW), 총손익금, 총수익률, 현재 USD/KRW 환율
2. 카테고리별 비중 파이차트
3. 카테고리별 수익률 바차트
4. 상세 종목 테이블 (컬럼: 카테고리, 종목명, 티커, 통화, 수량, 평단가, 현재가, 평가금액, 손익금, 수익률, 베타)
5. 자산 추이 라인차트 (`history.csv` 누적분 기반. 스냅샷이 1건뿐이면 "데이터가 쌓이면 추이가 표시됩니다" 안내 문구를 대신 표시)

### Tab2 "종목 관리"
- `st.data_editor`로 holdings 행 추가·수정·삭제
- 카테고리는 selectbox(기본 6개 + "직접 입력" 옵션)로, 오타로 인한 카테고리 분산을 방지하기 위해 기존 카테고리 선택을 우선 유도
- 종목명 선택 시 프리셋 딕셔너리에 있으면 티커 자동 입력, 없으면 티커 직접 입력
- "저장" 버튼 클릭 시 `holdings.csv`로 덮어쓰기 저장

## 6. 에러 처리

- 개별 티커 시세 조회 실패 시 해당 종목만 "시세 조회 실패" 경고를 표시하고 나머지는 정상 진행 (앱 전체가 죽지 않도록 함)
- `holdings.csv`가 없으면 빈 템플릿을 자동 생성
- 환율 조회 실패 시 마지막으로 캐시된 값을 유지하고 경고만 표시

## 7. 테스트 전략

- `portfolio.py`의 계산 함수(카테고리 집계, 비중, 수익률 등)에 대해 pytest 유닛테스트 작성
- `market_data.py`는 외부 API(yfinance) 의존이므로 목(mock) 처리해 별도 통합 테스트는 최소화
