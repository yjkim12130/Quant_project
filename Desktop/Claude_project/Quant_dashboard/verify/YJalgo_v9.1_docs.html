1. 프로젝트 개요 & 버전 히스토리

YJ-Quant는 레짐(Regime) 기반 적립식 투자 전략을 백테스팅하고 오늘의 매매 지침을 제공하는 Streamlit 대시보드입니다.

핵심 아이디어
시장 상태를 Bull / Bear / Panic 3가지로 분류하고, 상태별로 레버리지 배율을 달리 적용한 레버리지 ETF 적립식 투자. Panic 구간에서는 평소에 쌓아둔 CMA(파킹통장) 잔고를 ETF 저점 매수에 투입합니다.

2. 지표(Indicator) 계산 원리

모든 지표는 add_ind(data) 함수에서 일괄 계산됩니다. 입력은 일별 Price 컬럼을 가진 DataFrame.

MA_200 (200일 이동평균)

MA_200(t) = mean(Price[t-199 … t])

상태머신에 직접 사용되지는 않지만, dropna(subset=["MA_200"]) 조건으로 웜업(200거래일) 구간을 제거하는 데 쓰입니다. 웜업 데이터를 포함해서 지표를 먼저 계산하고, 이후 시뮬 시작 날짜로 필터링하는 방식이 v8.6 Fix-A의 핵심입니다.

Disp (이격률, Disparity)

Disp(t) = (Price(t) − MA_200(t)) / MA_200(t) × 100 (%)

현재 가격이 200일 이평선 대비 얼마나 이탈했는지. Bull→Bear 전환 조건에서 Disp < −3.0%와 AND로 묶여 하방 이탈 확인에 사용됩니다.

CCI (Commodity Channel Index)

CCI(t) = (Price(t) − SMA_200(t)) / (0.015 × MAD_200(t))
항목설명
SMA_200200일 단순이동평균 (= MA_200)
MAD_200200일 평균절대편차 = mean(|Price - SMA|)
0.015Lambert 상수 — 값이 ±100 내에 약 70~80% 분포하도록 정규화

CCI가 양수(>0)면 현재 가격이 이동평균 위 → 상승 추세. 음수(<0)면 하락 추세. 본 전략에서는 Bull↔Bear 전환 및 Panic 탈출 조건에 사용됩니다.

RSI (Relative Strength Index, 14일)

RSI = 100 − 100 / (1 + AG / AL)

AG = 14일 상승분 평균, AL = 14일 하락분 절댓값 평균. 70 이상 과매수, 30 이하 과매도. Bear→Bull 전환 및 Panic→Bear 탈출 조건에서 RSI 임계값과 비교합니다.

MDD (Maximum Drawdown, 252일 롤링)

MDD(t) = Price(t) / max(Price[t-251 … t]) − 1.0

최근 252거래일(약 1년) 고점 대비 현재 얼마나 하락했는지. 값은 항상 ≤ 0. Panic 진입 조건에서 MDD ≤ mdd_panic(기본 −0.15 = −15%)로 사용합니다.

VIX

S&P 500의 경우 ^VIX, Nasdaq은 ^VXN을 yfinance로 직접 수신. VIX가 없는 자산(KOSPI, 금 등)은 역사적 변동성으로 대체 계산합니다:

대체 VIX = rolling(20).std(Daily_Ret) × √252 × 100
💡 v8.6 Fix-C: 1일 시프트 제거
v8.5까지는 _s_VIX, _s_CCI 등 전날 값을 사용했으나, v7.1과 비교 시 신호가 1~3일 지연되는 문제가 발견되어 당일 값을 그대로 사용하도록 변경했습니다.

3. 상태머신 (Bull / Bear / Panic)

매 거래일마다 _state(cur, vix, cci, rsi, mdd, disp, p) 함수가 호출되어 다음 상태를 결정합니다.

🟦 Bull

상승 추세 구간

레버리지: lev_bull (기본 2.0배)

ETF 정규 적립 유지

🟧 Bear

하락 추세 구간

레버리지: lev_bear (기본 1.0배)

레버리지 축소, CMA 적립 강화

🟥 Panic

폭락 구간

레버리지: lev_panic (기본 1.5배)

CMA 드레인 매수 발동

전환 규칙 (우선순위 순)

모든 상태 → Panic  (최우선):   VIX ≥ vix_panic AND MDD ≤ mdd_panic
Panic → Bear (탈출):   CCI > 0 AND RSI > rsi_bear
Panic → Panic 유지: 위 조건 불충족 시
Bear → Bull:   CCI > cci_bull AND RSI > rsi_bull
Bear → Bear 유지: 위 조건 불충족 시
Bull → Bear:   CCI < cci_bear AND Disp < −3.0%
Bull → Bull 유지: 위 조건 불충족 시 
def _state(cur, vix, cci, rsi, mdd, disp, p):
    # ① 최우선: Panic 진입 (어느 상태에서든 즉시 Panic으로)
    if vix >= p["vix_panic"] and mdd <= p["mdd_panic"]:
        return "Panic"
    # ② Panic 탈출 조건
    if cur == "Panic":
        return "Bear" if (cci > 0 and rsi > p["rsi_bear"]) else "Panic"
    # ③ Bear→Bull 전환
    if cur == "Bear":
        return "Bull" if (cci > p["cci_bull"] and rsi > p["rsi_bull"]) else "Bear"
    # ④ Bull→Bear 전환 (기본 상태는 Bull)
    return "Bear" if (cci < p["cci_bear"] and disp < -3.0) else "Bull"
⚠️ 중요: Panic 최우선
VIX+MDD 조건은 함수 맨 첫줄에서 체크됩니다. Bear 상태에서도, Bull 상태에서도 즉시 Panic으로 전환. v8.5 버그 당시 이 순서가 반전되어 Panic이 억제되었습니다.

레버리지 비용 처리

레버리지 2배(예: TQQQ)는 지수 2배 수익을 추종하는 대신, 매일 레버리지 비용이 발생합니다:

일별 수익 = YS × (1 + Daily_Ret × lev − max(0, lev−1) × LEV_COST/252)

LEV_COST = 0.045 (연 4.5%). lev=1이면 비용 없음. lev=2이면 매일 4.5%/252 차감.

💡 음수 레버리지 (인버스)
lev_bear = −1.0 입력 시 Bear 구간에서 인버스 ETF 효과. 시장 하락 시 수익, 상승 시 손실. 단, max(0, lev−1) 조건으로 lev < 1 구간에서는 레버리지 비용 없음.

4. 전략 엔진 — run_beta / run_alpha

run_beta — ETF 기반 전략 (전략 0, 1)

매 거래일 루프를 돌며 아래 순서로 처리:

① 상태 결정 cur = _state(cur, vix, cci, rsi, mdd, disp, params)
→ 상태 변경 시 state_logs에 기록
② 레버리지 수익 반영 YS *= (1 + Daily_Ret × lev − 비용)
③ CMA 이자 적립 YC *= (1 + CMA_INTEREST/252)
④ 오늘 적립금 분배 YS += daily_stock_amount    YC += daily_cma_amount
→ daily_stock = budget × stock_ratio/18 ÷ 252
→ daily_cma = budget × (18−stock_ratio)/18 ÷ 252
⑤ Panic 드레인 (Panic 상태일 때) CMA 일부를 ETF로 이전
⑥ 기록 recs에 {time, yj_val, yj_st, yj_cs, state, leverage, total_principal} 저장
💡 stock_ratio / 18의 의미
18은 월 평균 거래일 수를 나타냅니다. stock_ratio=15이면 전체 월 적립금의 15/18을 ETF에, 3/18을 CMA에 배분. 매일 균등하게 나눠 적립하는 방식입니다.

run_alpha — TopN 종목 기반 전략 (전략 2, 3, 4)

run_beta와 구조는 동일하나, ETF 대신 전년도 시총 Top N 종목들의 평균 수익률을 추적합니다.

# 매일 TopN 종목 수익률 추적
tks_all = TOP10.get(yr-1, TOP10[max(TOP10)])[:tn]   # 전년도 시총 상위 N개
av_all  = [t for t in tks_all if t in sr.columns]   # 데이터 존재 종목만
ya_dca *= (1 + sr.loc[dt2, av_all].mean())              # 동일 가중 평균 수익률 적용

TopN 목록은 연도별 하드코딩(TOP10 딕셔너리, 2000~2026년). 전년도 기준이므로 해당 연도 초에 이미 알 수 있는 정보 사용 → 미래 데이터 참조 없음.

sim_start / sim_end와 웜업 처리

def run_beta(data, params, budget, inh=None, sim_start=None, sim_end=None, staged=False):
    df = add_ind(data)                              # 전체 데이터로 지표 계산 (웜업 포함)
    df = df.dropna(subset=["MA_200", "MDD"])       # MA_200 수렴 전 데이터 제거
    if sim_start: df = df[df.index >= pd.Timestamp(sim_start)]  # 이후 시뮬 구간만

fetch_start = max(start_year−3, asset_min_year)로 3년치 웜업 데이터를 미리 확보하고, sim_start 이전은 지표 계산에만 사용합니다. 이것이 v8.6 Fix-A의 핵심입니다.

상태 인수인계 (inh — inheritance)

WFV에서 IS 기간이 끝난 후 OOS 기간을 이어받을 때, 마지막 상태(자산 잔고, state, panic_cnt 등)를 넘겨받습니다. inh가 없으면 Bull 상태, 잔고 0으로 시작합니다.

5. Panic 매집 로직 — 반복매집 vs 단계매집

MDD 3단계 임계값 구조

Panic 구간에서 매집 발동은 mdd_threshold_sets와 drain_sets 파라미터로 제어됩니다.

단계MDD 조건드레인 비율(기본)의미
1단계MDD ≥ threshold[2] (예: 15%)drain[2] = 0.4소폭 하락, CMA 40% 투입
2단계MDD ≥ threshold[1] (예: 30%)drain[1] = 0.6중간 하락, CMA 60% 투입
3단계MDD ≥ threshold[0] (예: 45%)drain[0] = 1.0대폭락, CMA 전액 투입

MDD 값이 클수록(더 많이 빠질수록) 더 많은 CMA를 투입 — 역발상 저점매수 원리입니다.

🔁 반복매집 (staged=False)

Panic 구간 내 panic_period 거래일마다 조건 충족 시 반복 매수.

매수 금액 = min(CMA × drain_ratio / periodic_denom, CMA)

  • panic_period=1, periodic_denom=1 → 매일 드레인 비율만큼 매수
  • periodic_denom=5 → 드레인 비율의 1/5씩 분할 매수
  • CMA 빠른 소진 | 저점 공격적 매수에 유리

🎯 단계매집 (staged=True)

MDD 구간별 최초 1회만 매수. 2단계 진입해도 1단계로 역행 불가.

매수 금액 = min(CMA × drain_ratio, CMA)

  • 1차 발동 → 2차 → 3차 순으로만 진행
  • panic_stage 변수로 이미 발동된 단계 추적
  • CMA 보존 | 더 깊은 저점에 집중 매수

6. 그리드서치 & WFV (Walk-Forward Validation)

그리드서치 (run_grid)

지정된 파라미터 범위의 모든 조합을 탐색해 Calmar 비율이 가장 높은 파라미터를 찾습니다.

조합 수 = Π len(각 파라미터 리스트)

예: VIX[25,30] × MDD[−0.12,−0.15] × CCI_bull[50,100] = 8조합. 조합이 500개 초과 시 사이드바에 경고 표시.

# 정렬 기준: Calmar = 연수익률 / |MDD|
res = sorted(res, key=lambda x: x["calmar"], reverse=True)

Calmar를 기준으로 쓰는 이유: 수익률만 높은 파라미터는 MDD도 클 수 있음. Calmar는 위험 대비 수익 효율이므로 더 안정적인 전략을 선별합니다.

WFV (Walk-Forward Validation) 구조

과최적화(곡선 맞추기)를 방지하기 위해, 백테스트와 완전히 분리된 기간에서 성과를 검증합니다.

전체 기간: [───────────────────────────────────────]

Window 1: [IS 4년────────][OOS 1년]
Window 2: [IS 4년────────][OOS 1년]
Window 3: [IS 4년────────][OOS 1년]
IS(In-Sample): 이 기간으로 최적 파라미터 탐색
OOS(Out-of-Sample): IS 최적 파라미터를 OOS에 적용 → 실제 성과 측정

각 윈도우에서 IS 최적 파라미터를 OOS에 적용하고, OOS 수익이 양수인 윈도우 비율(승률)을 확인합니다. OOS 결과들을 연결해 누적 곡선을 만들고 전체 성과를 측정합니다.

순열 검정 (Permutation Test)

전략의 수익이 실제 패턴에서 기인한 것인지, 아니면 우연인지를 통계적으로 검증합니다:

p-value = P(무작위 레버리지 배열의 수익 ≥ 실제 전략 수익)

레버리지 배열을 200번 랜덤 셔플하여 귀무분포를 만들고, 실제 전략이 그 분포의 어디에 위치하는지 확인. p < 0.05면 통계적으로 유의미한 전략입니다.

7. 몬테카를로 & 블록부트스트랩 시뮬레이션

공통 원리

백테스트 결과(equity curve)에서 순수 수익률(적립금 제거)을 추출하고, 이를 재샘플링하여 미래 N년 경로를 1000회 시뮬레이션합니다.

순수 수익률(t) = (Value(t+1) − daily_contribution) / Value(t) − 1

몬테카를로 (mc_sim)

과거 일별 수익률 분포에서 독립 복원추출.

매 거래일마다 랜덤하게 수익률 하나를 선택하여 경로 생성.

8. 5종 전략 비교 구조

#전략명ETF 적립CMAPanic 드레인 대상함수
0ETF Only 전액(18/18) 매일 ETF 적립 없음— run_beta(stock_ratio=18)
1ETF+CMA M/18 ETF + (18-M)/18 CMA 적립 있음ETF 레버리지 run_beta(stock_ratio=M)
2TopN Only 전액 TopN 동일가중 적립 없음— run_alpha(stock_ratio=0, alpha_dca_ratio=1.0)
3TopN+CMA M/18 TopN + (18-M)/18 CMA 있음TopN 동일가중 run_alpha(stock_ratio=0, alpha_dca_ratio=M/18)
4ETF→TopN ★ M/18 ETF레버 + (18-M)/18 CMA 있음TopN 개별주 (선별방식 적용) run_alpha(stock_ratio=M, alpha_dca_ratio=0.0)
★ ETF→TopN 전략 권장 이유
평상시는 레버리지 ETF로 상승 수익 극대화. Panic 시에는 CMA를 개별 우량주(TopN)에 분산 매집 → 회복기에 레버리지 ETF + 저점 매입 종목 이중 수익 기대.

M은 사이드바의 stock_ratio (기본 15)입니다. v9.1 [R5] 수정으로 그리드서치 1위 파라미터가 올바르게 전달됩니다.

11. v9.1 변경사항 (R1~R5) 상세

[R1] 자산별 Start Year 최소 연도 확장

문제: v9.0까지 모든 자산의 백테스트 시작 연도 하한이 2000년으로 고정되어 있었음.

해결: ASSET_MIN_YEARS 딕셔너리를 추가하여 자산별 실제 데이터 가용 최소 연도를 정의.

ASSET_MIN_YEARS = {
    "S&P 500":   1950, "Nasdaq":    1971,
    "금(Gold)":  1979, "KOSPI":     1994,
    "Bitcoin":   2014, "Nikkei225": 1965, ...
}

사이드바 start_year 입력 범위를 _asset_min_yr부터로 동적 설정. 기본값은 max(min_yr+3, 2010).

[R2] yfinance repair=True 적용

문제: yfinance 기본 download() 함수는 주식 분할, 배당 조정 오류 등을 자동 수정하지 않음.

해결: yf.Ticker(sym).history(repair=True)로 자동 복구 우선 시도. 실패 시 기존 yf.download()로 fallback.

try:
    raw_h = yf.Ticker(ps).history(repair=True, auto_adjust=True, ...)
    if not raw_h.empty: df["Price"] = raw_h["Close"]
except:
    # fallback: download()
[R3] Panic TopN 종목 선별 방식 옵션

문제: 기존에는 시총 기준 TopN에 드레인 금액을 무조건 균등 배분.

해결: 패닉 시작일 이후 누적 수익률 기준으로 하락상위(역발상) / 상승상위(모멘텀) 선별 옵션 추가.

선별된 종목은 ya_p_val에 별도 추적하여 시총기준 ya_dca와 구분 관리.

[R4] 산업분석 ETF 구성종목 동적 조회

문제: 산업분석 탭의 종목 풀이 사전 정의된 기업들로만 제한되었음.

해결 1: yf.Ticker("QQQ").get_holdings()로 나스닥100 상위 50종목 동적 조회.

해결 2: yf.Ticker("SPY").get_holdings()로 S&P500 상위 50종목 동적 조회.

해결 3: KODEX200_TOP30 정적 리스트(2025년 기준 시총 상위 30종목) 추가.

ETF 구성 종목은 📦 태그로 표시, 자동 섹터 분류 시도 후 실패 시 수동 지정 UI 제공.

[R5] 5종비교 파라미터 버그 수정

문제: 5종비교 탭 실행 시 그리드서치 1위 파라미터가 아닌 첫 번째 파라미터 조합이 사용됨 → ETF+CMA 결과가 백테스트 탭과 불일치.

해결: st.session_state["best"]가 있으면 1위 파라미터 우선 사용. 없으면 첫 번째 값으로 fallback + 안내 메시지 표시.

if "best" in st.session_state:
    best_p = st.session_state["best"]
    p_base = {k: best_p.get(k, ...) for k, v in grid_params.items()}
else:
    p_base = {k: v[0] if isinstance(v, list) else v for ...}

[ 사이드바 입력 ]
자산 선택 → 기간 → 연간투자금 → 레버리지 → 파라미터 → 매집방식 → Panic선별

[ 데이터 수집 ] (캐시 TTL=3600초)
fetch_asset(name, fetch_start) ← yf.Ticker.history(repair=True) or yf.download()
fetch_stocks(start) ← SPY + TOP10 전 종목 일괄 수신
fetch_all_assets(start) ← 10개 자산 일괄 (Tab1용)

[ 지표 계산 ]
add_ind(data) → MA_200, Disp, CCI, RSI, MDD 추가
dropna(MA_200, MDD) → 웜업 200일 제거
sim_start 필터링 → 시뮬 구간만 추출

[ 전략 실행 ]
run_beta() → ETF 기반 (전략 0, 1)
↓ _state() 매일 호출 → Bull/Bear/Panic 결정
↓ 레버리지 수익 반영 + CMA 이자 + 적립금 분배
↓ Panic 시 드레인 (staged or 반복)
run_alpha() → TopN 기반 (전략 2, 3, 4)
↓ 동일 흐름 + ya_dca(TopN) / ya_p_val(선별종목) 별도 추적

[ 최적화 ]
run_grid() → 전 파라미터 조합 탐색 → Calmar 기준 정렬
run_wfv() → IS 최적화 → OOS 검증 반복 → 순열검정

[ 결과 표시 ]
equity_curve → fig_eq, fig_dd, fig_yr, fig_regime
metrics → 총수익률, 연수익률, MDD, Sharpe, Calmar, 최종자산
_ai_box() → 수치 기반 자동 해석 텍스트
mc_sim / boot_sim → 미래 시뮬레이션 경로 및 분포

성과 지표 계산 공식

지표공식판단 기준
총수익률(최종자산 / 총투입원금 − 1) × 100%—
연수익률(CAGR)(최종자산 / 총투입원금)^(1/기간년수) − 1기간은 달력일 기준 (365.25일/년)
MDDmin((자산 / 누적최고점) − 1)−30% 이하 주의
Calmar연수익률 / |MDD|≥0.3 양호, ≥0.5 우수
Sharpe일평균수익 / 일표준편차 × √252≥1.0 우수
💡 CAGR 계산 주의
v8.4 버그: 거래일(252일/년) 기준으로 CAGR을 계산하여 과대계상. v8.5 이후 달력일(365.25일/년) 기준으로 수정.
