1. 요구사항 재정리

원문(sub1)을 풀어보면 요구는 세 갈래입니다.

  • 원천 데이터: 2024년부터 약 2년간 오재승 자문역이 리딩한 채팅방 원문(chathistory.txt) + 2026.05.26부터 합류한 빈규리 CPA의 스몰캡 분석 + 유튜브 강의 영상 — 두 자문역이 강조한 핵심 매매·분석 기법이 유튜브 링크로도 존재(자막 추출해 RAG 합류).
  • 만들 것: 두 자문역의 리딩 정보·의견·인사이트를 학습/참조하는 (A) 매크로 경제·시황 분석 에이전트와 (B) 개별기업 분석 에이전트.
  • 녹일 곳: 기존 퀀트 대시보드(YJalgo)에 통합. 향후 v9.3과 병합하여 단일 앱으로.
  • 사용 범위(확정): 본인 개인 내부 사용 전용. 외부 서비스·배포 없음. → 목표는 오직 "내 투자 의사결정 품질·예측력 향상".
  • ★ 시한(2차 추가): 두 자문역이 약 6개월 뒤 활동 종료. → 핵심 요구가 "그들의 발언 열람"에서 "그들의 가치관·판단기준을 룰북으로 증류해 떠난 뒤에도 신규 종목·미래 시황에 동일 기준 적용"으로 바뀜. 즉 페르소나 보존·이식이 진짜 목표.

분석 축은 시황분석(매크로 + 기술기업 기술분석)과 개별기업분석(재무제표, 독점력/해자)으로 명시되어 있습니다.

2. 데이터 진단 — 원문 샘플로 확인한 특성

원문을 표본 점검한 결과, 데이터 가치는 높지만 전처리 난이도가 핵심 변수입니다.

✅ 강점 (활용 가치 높음)

  • 오재승 자문역의 일간 아침 시황이 반복 등장 — 금리/연준/FOMC/반도체/외국인 수급 등 매크로 논리 일관성 추적 가능.
  • 빈규리 CPA의 분석은 사업부문 → 시장규모 → 해자 → 결론 구조가 또렷함(예: 헥토파이낸셜 분석). 개별기업 에이전트의 좋은 템플릿.
  • 같은 종목·테마가 반복 언급되어 "자문역의 일관된 관점"을 종목 단위로 모을 수 있음.
  • 날짜·시각·발화자가 라인 단위로 찍혀 있어 타임스탬프 파싱이 쉬움.

⚠️ 약점 (전처리 필요)

  • 잡담·입장 알림·이모티콘이 대량 혼입("…님이 들어왔습니다", "사진", "이모티콘"). 노이즈 필터링 필수.
  • 핵심 근거가 이미지/PDF("사진", "파일: …pdf")로만 존재 — 텍스트엔 안 남음. OCR 없으면 누락.
  • 발화가 여러 줄로 쪼개짐 — 한 생각을 1메시지로 재조립(청킹)해야 의미 보존.
  • 구어체·축약·오타 많음. 종목명이 한글/티커 혼용.
핵심 시사점 — 데이터의 80%는 노이즈일 가능성이 큽니다. "발화자=오재승/빈규리 + 의미있는 분석 문단"만 추출하는 전처리 파이프라인이 프로젝트 성패의 절반입니다.

신규 데이터 소스 — 유튜브 강의 영상 2차 추가 · 추출 완료

두 자문역이 강조한 핵심 기법이 유튜브 강의로도 존재합니다. youtube-transcript-api로 한국어 자동생성 자막을 추출해 같은 RAG 파이프라인에 합류시켰습니다. 채팅 원문보다 가치가 높은 이유:

  • 채팅은 여러 줄로 쪼개진 단편이지만, 영상은 한 기법을 처음부터 끝까지 구조적으로 설명 → 판단기준·룰 추출에 이상적.
  • 채팅에서 "사진/PDF로만 존재"하던 핵심 근거(§2 약점)가 영상에선 말로 설명돼 있어 OCR 문제 일부 우회.
  • 발화자가 명확(전부 자문역 본인) → 노이즈 필터링 거의 불필요.

기술 스택 제안 (기존 환경과 호환)

  • 전처리: Python(정규식으로 날짜, 시각, 발화자 : 내용 파싱). 현재 프로젝트가 Python 기반이라 그대로 활용.

  • 임베딩: 한국어 강한 모델 권장 — OpenAI text-embedding-3 또는 로컬 bge-m3(비용 0, 오프라인).
  • 벡터DB: Chroma 또는 FAISS — 로컬 파일로 충분(데이터 10MB 규모는 가벼움).
  • LLM: Claude / GPT API. 근거 인용·한국어 요약 품질 양호.
  • UI: 기존 Streamlit 대시보드에 탭 추가(§7 참조).
데이터가 10MB로 작아 인프라 부담이 거의 없습니다. 임베딩 1회 비용과 질의당 LLM 호출 비용만 들고, 로컬 벡터DB라 별도 서버 불필요합니다.

5. 두 개의 에이전트 설계 (우선순위 재조정)

우선순위 확정 (2026-06-04) — 정량 예측·대응력은 v9.3 완료, 시황 해설은 비교적 가벼운 기능. 진짜 빠져있는 핵심은 "빈규리 자문역처럼 개별기업을 깊게 파는 분석"이며, v9.3엔 이 기능이 전무합니다. → (B) 개별기업 분석 에이전트가 이 프로젝트의 메인 산출물이고, (A) 시황 에이전트는 보조입니다.

★ 0순위 산출물 — "자문역 룰북" 증류 신규 핵심

자문역이 6개월 뒤 사라지므로, 두 에이전트보다 먼저 만들어야 할 토대는 두 사람의 판단기준을 명시적 룰(if-then)로 증류한 "룰북"입니다. 이게 있어야 그들이 떠난 뒤에도 한 번도 본 적 없는 신규 종목·미래 시황에 동일 기준을 적용할 수 있습니다. 단순 인용이 아니라 판단 프레임의 이식.

★ 예측력을 실제로 확보하는 법 (이 프로젝트의 핵심)

가장 중요한 메시지 — "자문역 말을 검색해 보여주는 봇"은 예측력이 없습니다. 그건 그냥 과거 의견 열람기입니다. 예측력은 그 의견이 실제로 맞았는지 데이터로 검증하고, 정량 신호와 결합할 때만 생깁니다. 여기에 프로젝트의 80% 가치가 있습니다.

레버 0 — ★ 6개월 안에 페르소나를 '검증 완료'로 굳히기 신규 1순위

자문역이 6개월 뒤 사라지므로, 이 6개월이 "정답지가 살아있는" 유일한 기간입니다. 에이전트가 신규 종목·시황에 대해 "오재승/빈규리라면 이렇게 볼 것"이라 예측 → 실제 두 분의 당일 발언과 대조 → 룰북·페르소나가 본인을 얼마나 정확히 모사하는지 매일 측정·튜닝합니다.

  • 1순위 KPI 재정의: "자문역 콜이 시장에서 맞았나"보다 "내 에이전트가 자문역 본인을 얼마나 잘 흉내내나"(모사 정확도)가 먼저.
  • 방법: 같은 종목·시황에 대해 에이전트 출력 vs 실제 자문역 발언을 룰 단위로 일치/불일치 채점 → 어긋나는 룰을 6개월간 보정.
  • 마감 효과: 떠난 뒤엔 이 대조가 영영 불가능 → 은퇴 전 페르소나에 '검증 도장'을 찍어두는 것이 프로젝트 성공의 정의.

레버 1 — 자문역 콜의 적중률(Hit-rate) 측정

자문역이 "○○ 매수/긍정" 발언을 한 날짜·종목을 추출 → 그 시점 이후 실제 주가(yfinance)로 N일/N개월 수익률을 자동 계산 → 콜별 적중 여부 기록.

  • 산출물: "오재승 자문역의 매수 콜 적중률 ○○%, 평균 +○○%(30일)", "반도체 콜은 잘 맞고 스몰캡 콜은 약함" 같은 정량 신뢰도 스코어.
  • 효과: 어떤 종류의 인사이트를 믿을지 데이터로 결정 → 맹신/생존편향 차단이 곧 예측력.
  • 이미 v9.3에 yfinance·수익률 계산 인프라가 있으므로 재사용 가능.

레버 2 — 정성(자문역) × 정량(v9.3 신호) 결합

한쪽만 보면 약하지만 두 신호가 같은 방향일 때 베팅하면 승률이 올라갑니다. 예: v9.3이 "매수 레짐"이고 + 자문역도 같은 종목을 긍정 → 강한 시그널. 엇갈리면 보류. 이 합의(consensus) 룰이 단일 신호보다 예측력이 높은 게 일반적입니다.

레버 3 — 룩어헤드 없는 정직한 검증

적중률을 측정할 때 발언 시점 이후 데이터로만 수익률을 계산해야 진짜 예측력입니다. 발언 타임스탬프를 엄격히 지키고, "사후에 맞아 보이는 발언"을 거르세요. 이게 무너지면 화면상 숫자만 좋고 실전에선 안 맞습니다.

요약 — 개인용이라 마음껏 "예측·추천"을 붙여도 되지만, 그 예측의 근거는 LLM의 말빨이 아니라 적중률 데이터여야 합니다. 이 검증 레이어가 없으면 "그럴듯하지만 안 맞는 봇"이 되고, 있으면 "믿을 만한 콜만 골라주는 봇"이 됩니다.

6. 리스크 · 반드시 짚을 것 (개인용 기준 재평가)

개인 내부 사용으로 확정되어 법적·서비스·개인정보 외부유출 리스크는 대부분 해소되었습니다(아래 표에서 회색 처리). 대신 예측력을 좌우하는 리스크(신뢰성·룩어헤드·환각)가 오히려 더 중요해집니다.
리스크내용완화책
원천 신뢰성 최우선 자문역 발화가 항상 맞았는지 미검증. 샘플엔 "내가 다 맞췄다"식 자기서사, 만수르/페어트레이딩 등 마케팅성 표현도 보임. 맞은 예측만 기억되는 생존편향이 곧 예측력 저하. §5★ 적중률 측정으로 정면 돌파 — 콜별로 실제 주가 대비 성과를 매겨 믿을 콜/못 믿을 콜을 데이터로 구분.
미래정보 혼입(룩어헤드) 최우선 적중률 측정 시 발언 시점 이후 데이터만 써야 함. 안 그러면 화면 숫자만 좋고 실전에서 안 맞음. 발화 타임스탬프 엄격 유지, 수익률은 발언일 이후 구간으로만 계산.
LLM 환각 중요 모델이 자문역이 안 한 말을 지어내면 잘못된 근거로 베팅하게 됨. RAG로 검색된 원문 범위 내 답변 강제 + 모든 주장에 날짜 인용 의무화. 근거 없으면 "해당 발화 없음".
법적/저작권 개인용→해소 서비스화 시 투자자문업법·저작권 문제. 개인 내부 사용이라 해당 없음. 외부 공유·배포만 하지 않으면 됨. (현 범위에선 비이슈)
개인정보 완화 채팅에 제3자 실명·사적 대화 포함. 외부 유출 시 문제. 외부 미배포로 위험 낮음. 그래도 전처리에서 두 자문역 발화만 추출하면 품질·프라이버시 모두 개선.
방향 전환 요약 — 개인용 확정으로 "추천·예측 봇"을 자유롭게 만들 수 있습니다. 대신 신뢰성·룩어헤드·환각 3가지가 예측력의 진짜 적이며, 모두 §5★ 적중률 검증 레이어로 방어됩니다.

7. YJalgo v9.3 통합 방안

현재 v9.3는 레짐 기반 적립식 백테스트 대시보드(Streamlit)입니다. 자문 에이전트는 정성(텍스트) 레이어로, 기존 정량 엔진과 느슨하게 결합하는 것이 안전합니다.

단계적 통합 (권장)

  • 1단계 — 독립 모듈: 자문 에이전트를 별도 Python 모듈/별도 Streamlit 페이지로 먼저 완성. v9.3 코드와 분리해 리스크 격리.
  • 2단계 — 탭 통합: v9.x 대시보드에 "자문역 인사이트" 탭 추가. 백테스트와 한 앱, 코드는 분리 유지.
  • 3단계 — 종목 연동: 사용자가 대시보드에서 보고 있는 종목을 자동으로 에이전트 질의에 넘겨, "이 종목에 대한 자문역 코멘트"를 같은 화면에서 표시.
통합의 시너지 — 정량 신호(레짐/RSI/VIX/거래비용 반영 수익률)와 정성 관점(자문역 코멘트)을 한 종목에서 교차 검증. 예: 대시보드가 "매수 레짐" 신호를 줄 때, 같은 시점 자문역이 그 종목을 어떻게 봤는지 즉시 대조.

통합 시 주의

  • v9.3는 안정 버전이므로 기존 코드 직접 수정 최소화 — 새 파일/탭으로 얹기.
  • LLM API 키 관리(.streamlit/secrets 또는 환경변수). 키 하드코딩 금지.
  • 임베딩 인덱스는 사전 빌드 후 파일로 배포 — 앱 구동 시 매번 재임베딩하면 느림/비용↑.
  • 버전 명명: 통합본은 v9.4 또는 별도 트랙으로. (메모상 v9.4 이후 Plan 7과 충돌 없는지 확인)

8. 열린 질문 (착수 전 결정 필요)
