01프로젝트 개요 & 투자 철학

대부분의 주식 분석은 매크로 지표 중심입니다. 이 프로젝트는 시야를 개별주, 특히 시가총액이 작은 종목(KOSPI·KOSDAQ·NASDAQ)으로 돌립니다. 네이버 종목 토론방의 게시글을 모아 감성을 분석하고, 대중의 심리와 반대되는 의사결정으로 시세 차익을 노립니다.

핵심 인사이트 — "인간지표(人間指標)"
토론방이 과열되어 모두가 환호할 때(극단적 낙관) → 고점 신호.
모두가 패닉에 빠져 비관할 때(극단적 공포) → 저점 신호.
군중과 역행하는 신호를 점수로 만들어 개별주를 추천하는 것이 목표입니다.

STEP 1 · 모니터링 종목 등록

분석할 종목을 DB에 추가합니다. 첫 실행 시 DB와 테이블이 자동 생성됩니다.

방법 A — 즉시 1회 실행 (테스트·수동 수집):

06크롤러 동작 원리

NaverDiscussionCrawler는 종목별 토론방을 페이지 단위로 훑으며 게시글을 수집합니다.

수집 흐름

  1. 최신 nid 조회 — DB에 이미 저장된 가장 최신 글 번호(nid)를 가져옵니다.
  2. 목록 페이지 파싱 — board.naver에서 제목·날짜·조회수·추천·비추천을 추출합니다 (table.type2 기준).
  3. 조기 종료(중복 방지) — 저장된 nid 이하 글을 만나면 그 즉시 멈춥니다. 이미 수집한 글을 다시 긁지 않습니다.
  4. 본문 수집 — 신규 글만 board_read.naver에 접속해 본문 텍스트를 가져옵니다 (fetch_content=False로 끌 수 있음).
  5. 저장 — INSERT OR IGNORE로 중복 nid는 건너뛰고 신규 건수만 반환합니다.
매너 크롤링 — 요청 사이에 CRAWL_DELAY(기본 1.5초) 지연을 둡니다. 인코딩은 네이버 금융 특성상 euc-kr로 디코딩하며, 실패 시 MAX_RETRIES(3회)까지 지수적으로 대기 후 재시도합니다.

한 종목 직접 크롤링 (코드 예시)

from crawler.naver_discussion import NaverDiscussionCrawler
from database.schema import init_db

init_db()
crawler = NaverDiscussionCrawler()
new_count = crawler.crawl_stock("005930", max_pages=5)
print(f"신규 {new_count}건 저장")

07데이터베이스 스키마

SQLite 파일 한 개(data/emotion_analysis.db)에 두 개의 테이블이 있습니다.

📋 stocks — 모니터링 종목

컬럼타입설명
codeTEXT PK종목 코드 (예: 005930)
nameTEXT종목명
marketTEXTKOSPI / KOSDAQ / NASDAQ 중 하나
activeINTEGER1=활성(크롤링 대상), 0=비활성
created_atTEXT등록 시각 (자동)

📋 posts — 토론방 게시글

컬럼타입설명
idINTEGER PK자동 증가 ID
stock_codeTEXTstocks.code 참조
nidTEXT네이버 글 번호 (종목+nid 유니크)
title / contentTEXT제목 / 본문
author / post_dateTEXT작성자 / 작성일
views / likes / dislikesINTEGER조회수 / 추천 / 비추천
sentiment_scoreREALPhase 2 감성 점수 (-1.0 ~ 1.0), 미분석은 NULL
crawled_atTEXT수집 시각 (자동)
중복 방지 설계 — UNIQUE(stock_code, nid) 제약 + INSERT OR IGNORE 조합으로 같은 글이 두 번 저장되지 않습니다. 조회 성능을 위해 (stock_code, post_date)와 (stock_code, sentiment_score) 인덱스를 둡니다.

08자동 스케줄링

scheduler.py는 APScheduler의 BlockingScheduler로 장 시작 전(08:50)과 장 종료 후(15:40)에 크롤링을 자동 실행합니다. 시간대는 Asia/Seoul로 고정됩니다.

시각의미
08:50장 시작 직전 — 개장 전 심리 스냅샷
15:40장 종료 직후 — 마감 후 반응 수집

실행 시각은 config.py의 SCHEDULE_TIMES 리스트로 자유롭게 추가/변경할 수 있습니다.

서버 상주 팁 — 집 PC에서 스케줄러를 띄워 두고 Tailscale로 원격 접속하면, 외부에서도 같은 네트워크처럼 로그를 확인할 수 있습니다. (요구사항 정의서의 운영 시나리오)

10감성 점수 산출 원리 Phase 2

시스템의 모든 분석은 결국 한 숫자, posts.sentiment_score(−1.0~1.0)에서 출발합니다. 이 섹션은 게시글 한 건의 텍스트(제목·본문)가 어떻게 하나의 감성 점수로 변환되는지의 원리를 설명합니다.

정의 — 감성 점수 s ∈ [−1.0, +1.0]
+1.0 극단적 낙관(환호) · 0.0 중립 · −1.0 극단적 비관(공포). 미분석 글은 NULL로 두고, 배치로 채웁니다.

세 가지 접근법 비교

주식 토론방 텍스트는 은어·축약어·반어·도배가 많아 일반 감성분석기가 잘 듣지 않습니다. 정확도와 구현 난이도의 트레이드오프에 따라 단계적으로 도입합니다.

방식원리장점 / 단점
① 사전 기반
(Lexicon)		감성 단어 사전에서 단어별 점수를 찾아 합산·평균👍 빠름·투명·라벨 불필요 / 👎 문맥·반어 약함
② 머신러닝
(KoBERT·KcELECTRA)		한국어 사전학습 모델을 감성 라벨로 미세조정(fine-tune)👍 문맥 이해 정확 / 👎 라벨링·GPU·속도 부담
③ 하이브리드
(권장 시작점)		사전 기반 점수 + 도메인 규칙(은어·이모지·강조) 가중 보정👍 라벨 없이 도메인 적응 / 👎 규칙 유지보수 필요
채택 전략 — Phase 2는 ③ 하이브리드(사전+규칙)로 빠르게 점수를 채워 백테스트를 돌리고, 데이터가 쌓이면 그 결과를 약지도 라벨(weak label) 삼아 ② ML 모델로 업그레이드합니다.

STEP 1 · 전처리 (Preprocessing)

  • 정제 — HTML 태그·URL·반복문자(ㅋㅋㅋㅋ→ㅋㅋ) 정규화, 공백 정리
  • 토큰화 — 한국어 형태소 분석기(Okt/Mecab)로 명사·형용사·어미 분리
  • 도배 필터 — 동일 작성자·동일 문구 반복 글은 1건으로 축소(과열 점수 왜곡 방지)

STEP 2 · 감성 사전 매칭 (Lexicon Scoring)

기반 사전으로 KNU 한국어 감성사전을 쓰되, 토론방 특유의 도메인 사전을 덧붙이는 것이 정확도의 핵심입니다.

분류예시 단어/표현극성
강한 긍정떡상, 가즈아, 상한가, 익절, 매수각, 우상향+0.8 ~ +1.0
약한 긍정반등, 저점매수, 기대, 호재+0.3 ~ +0.6
중립보유, 횡보, 관망, 공시0.0
약한 부정물타기, 조정, 불안, 약세−0.3 ~ −0.6
강한 부정떡락, 손절, 폭락, 상폐, 패닉, 존버지옥−0.8 ~ −1.0
도메인 사전이 필수인 이유 — "떡상"·"가즈아"는 일반 사전엔 없고, "물리다"·"존버"는 일상어와 의미가 다릅니다. 토론방 은어를 직접 등록해야 일반 감성분석기 대비 정확도가 크게 오릅니다.

의문/반어물음표·반어 패턴 → 신뢰도 하향"이게 호재냐?" → 약화

STEP 4 · 집계 & 정규화 (−1.0 ~ 1.0)

토큰별 점수를 글 단위 하나의 값으로 합치고 [−1, 1]로 압축합니다. 긴 글이 점수를 독식하지 않도록 평균 + 길이 보정을 쓰고, 제목은 본문보다 강하게 가중합니다.

# analysis/sentiment_model.py (개념)
raw   = Σ(token_score · weight) / Σ|weight|     # 가중 평균
score = tanh(raw · k)                        # [-1,1]로 부드럽게 압축

# 제목 가중(본문보다 함축적·자극적) 예시
final = 0.6 · score_title + 0.4 · score_body
왜 tanh인가 — 합산값은 단어 수에 따라 무한정 커질 수 있습니다. tanh는 어떤 입력이든 (−1, 1) 범위로 매끄럽게 눌러주어, 글 길이에 둔감하고 극단값이 포화(saturate)되는 안정적 점수를 만듭니다.

STEP 5 · 저장 & 배치

미분석 글을 골라 점수를 매기고 되돌려 씁니다. 이미 마련된 DB 함수와 그대로 연결됩니다.

from database.db import get_posts_without_sentiment, update_sentiment
from analysis.sentiment_model import score_text

for post in get_posts_without_sentiment(limit=500):
    s = score_text(post["title"], post["content"])   # -1.0 ~ 1.0
    update_sentiment(post["id"], s)
다음 단계 연결 — 이렇게 채워진 글 단위 점수가 바로 다음 섹션 STEP A · 일별 심리 집계의 입력이 됩니다. 글 → 점수 → 일별 집계 → 역행 신호로 흐릅니다.
품질 관리 — 사전·규칙은 반드시 사람이 라벨링한 검증셋으로 정확도(Accuracy·F1)를 측정하며 튜닝하세요. 라벨 없이 임의 조정하면 백테스트 함정(과최적화)이 점수 단계에서부터 시작됩니다.

11가격–심리 상관 & 백테스트 원리 Phase 2

이 단계는 역행 투자 머신의 심장부입니다. "군중 심리가 정말로 주가의 반전을 예측하는가?"라는 질문을, 수집한 토론방 심리와 실제 가격 데이터를 정렬해 역사적으로 검증(백테스트)합니다. 감을 시그널로, 시그널을 검증된 전략으로 바꾸는 과정입니다.

핵심 가설 (Contrarian Hypothesis)
H₁ · 토론방 심리가 극단적 낙관(과열)으로 치우치면 → 이후 수익률은 음(-)으로 회귀한다 (고점 신호).
H₂ · 심리가 극단적 비관(공포)으로 치우치면 → 이후 수익률은 양(+)으로 회귀한다 (저점 신호).
즉 심리는 평균회귀(mean-reverting)하며, 극단치는 가격의 단기 반전을 선행한다는 것을 통계로 입증하는 것이 목표입니다.

STEP A · 일별 심리 집계 (Daily Sentiment Aggregation)

개별 게시글의 sentiment_score(−1.0~1.0)는 노이즈가 큽니다. 이를 (종목 × 날짜) 단위로 묶어 안정적인 일별 심리 지표를 만듭니다. 단순 평균뿐 아니라 관심도·논쟁도·극단성까지 함께 산출하는 것이 핵심입니다.

지표정의 / 수식의미
sent_mean해당 일 글들의 감성 평균 mean(score)그날의 전반적 분위기
sent_weighted조회·추천 가중 평균
Σ(score·wᵢ)/Σwᵢ, wᵢ=log(views+likes+1)		영향력 큰 글에 가중 → 여론 무게중심
post_volume해당 일 글 수 COUNT(*)관심도/과열도 — 급증은 군중 쏠림 신호
sent_std감성 표준편차 std(score)의견 분산 = 논쟁도 (낮을수록 한쪽 쏠림)
extreme_ratio|score| > 0.6인 글 비율극단적 환호/패닉의 강도
# analysis/sentiment_aggregator.py (개념)
# posts 테이블 → (종목, 날짜)별 일별 심리 지표
daily = (df
    .groupby(["stock_code", "date"])
    .agg(
        sent_mean   = ("sentiment_score", "mean"),
        sent_std    = ("sentiment_score", "std"),
        post_volume = ("sentiment_score", "size"),
    ))

STEP B · 가격 데이터 정합 & 미래수익률 (Price Alignment)

일별 심리에 같은 종목의 OHLCV 가격을 붙입니다. 국내는 FinanceDataReader, 해외는 yfinance로 종가를 받습니다. 백테스트의 라벨이 될 미래수익률(forward return)을 계산합니다.

# k일 뒤 종가 기준 미래수익률 (k = 1,3,5,10 ...)
fwd_ret_k = close.shift(-k) / close - 1
미래참조 편향(Look-ahead Bias) 절대 금지
크롤링 시각은 08:50(장 시작 전)·15:40(장 종료 후)입니다. 따라서 15:40에 집계된 심리는 그날 종가가 확정된 뒤의 정보 → 매매는 익일(t+1) 시가부터 가능하다고 보수적으로 가정해야 합니다. 오늘 심리로 오늘 종가에 진입하면 결과가 비현실적으로 좋아집니다(미래 정보 누수).

STEP C · 심리 지표 정규화 (Normalization)

종목마다 토론 활성도·감성 베이스라인이 다르므로 절대값 비교는 무의미합니다. 각 종목의 자기 과거 분포 대비 얼마나 극단인지를 봐야 합니다. 롤링 Z-score가 핵심입니다.

지표수식해석
심리 Z-score(sent_mean − μ₆₀) / σ₆₀
(최근 60일 롤링)		+2↑ 과열 · −2↓ 공포
과열도(Buzz)post_volume의 롤링 Z-score관심 급증 = 군중 쏠림 가속
심리 모멘텀sent_mean − sent_mean.shift(d)분위기 변화 속도/방향
왜 Z-score인가 — 소형주는 글이 적어 하루 평균이 출렁입니다. 롤링 Z-score는 종목별 기준선(상대화)을 만들어 KOSPI 대형주와 KOSDAQ 소형주를 같은 잣대로 비교하게 합니다.

STEP D · 상관관계 분석 (Correlation & Lead-Lag)

"심리가 가격을 선행하는가"를 보려면 시차 상관(lagged correlation)이 필수입니다. 오늘 심리와 k일 뒤 수익률의 상관을 k별로 계산합니다.

# 시차 상관: 심리(t) vs 미래수익률(t+k)
for k in [1, 3, 5, 10]:
    ic = spearman(sent_z[t], fwd_ret_k[t])   # 순위상관 = IC
방법쓰임
Pearson선형 관계. 이상치에 민감 → 보조용
Spearman(순위)비선형·이상치 강건. 주력 — 퀀트의 IC(정보계수)와 동일 개념
IC (Information Coefficient)심리 신호와 미래수익률의 순위상관. 역행 가설이면 IC가 음수(과열↑→수익↓)일 때 가설 성립
판독법 — 역행 전략은 심리 Z-score와 미래수익률의 IC가 유의하게 음수(−)여야 합니다. 시차 k별 IC 곡선이 어느 구간(예: t+3~t+5)에서 가장 강한 음의 값을 갖는지가 곧 최적 보유기간의 힌트가 됩니다.

STEP E · 역행 신호 생성 (Contrarian Signal)

정규화된 심리 지표를 임계값(threshold)으로 매매 신호로 변환합니다.

조건해석신호
심리 Z ≤ −2 & 과열도 ≥ +1관심 급증 + 극단 공포 → 투매매수(롱)
심리 Z ≥ +2 & 과열도 ≥ +1관심 급증 + 극단 환호 → 과열청산/회피
−2 < Z < +2중립 구간관망
과열도 필터를 함께 쓰는 이유 — 글이 2~3건뿐인 날의 극단 평균은 통계적 우연입니다. post_volume 과열도 조건을 AND로 걸어 "많은 사람이 동시에 극단으로 쏠린 날"만 신호로 인정해 노이즈를 거릅니다.

STEP F · 백테스트 엔진 (Backtest Engine)

신호를 과거 가격에 적용해 실제로 돈을 벌었을지 모의 매매합니다.

요소규칙(예시)
진입매수 신호 다음 거래일(t+1) 시가 매수
청산보유 N일 경과 / 청산 신호 / 손절·익절 도달
비용수수료+세금+슬리피지 (왕복 ≈ 0.3~0.5%) 반드시 차감
포지션동일가중 또는 신호강도(|Z|) 비례 배분
백테스트 3대 함정
① 미래참조(Look-ahead) — 확정 안 된 가격/정보로 매매. 항상 신호는 t, 체결은 t+1.
② 생존편향(Survivorship) — 상장폐지·거래정지 종목 제외 시 수익률 과대평가.
③ 데이터 스누핑/과최적화 — 임계값(±2 등)을 데이터에 맞춰 끼우면 미래엔 무너짐. In-sample / Out-of-sample 분리와 Walk-forward 검증 필수.

13문제 해결 (FAQ)

Q. 크롤링했는데 0건만 저장돼요.

이미 같은 글을 수집한 경우 정상입니다(조기 종료). 새 글이 없으면 0건이 맞습니다. 또는 네이버 HTML 구조가 바뀌어 table.type2 파싱이 실패했을 수 있으니 data/crawler.log를 확인하세요.

Q. 한글이 깨져요.

네이버 금융은 euc-kr 인코딩입니다. 크롤러는 이를 자동 처리하지만, DB를 외부 도구로 열 때는 UTF-8 지원 뷰어를 사용하세요.

Q. "모니터링 종목이 없습니다" 경고가 떠요.

add_stock.py로 종목을 먼저 등록해야 합니다. 활성 종목(active=1)만 크롤링 대상입니다.

Q. 요청이 자주 실패/차단돼요.

CRAWL_DELAY를 늘리고(예: 2.5~3초) MAX_PAGES_PER_STOCK을 줄이세요. 등록 종목이 많을수록 한 번에 보내는 요청량이 커집니다.

Q. ModuleNotFoundError: crawler 가 떠요.

반드시 프로젝트 루트에서 모듈 방식으로 실행하세요: python -m crawler.scheduler (파일을 직접 python crawler/scheduler.py로 실행하면 import 경로가 어긋납니다).
