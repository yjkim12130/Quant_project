# [백로그] Family B — 미국·한국 증시·정책 브리핑 (2페이지 세트)

- **상태**: 미착수 — 착수 전 별도 브레인스토밍 세션 1회 필요(이 문서는 스펙이 아니라 잊지 않기 위한 착수 전 메모)
- **참고**: [[project-daily-market-dashboard]] Family B, 예시 이미지 5개 인스턴스 확인(2026-08-17)

## 알려진 것

- 2페이지 세트: PAGE 1/2(한국 증시 뉴스보드 — KOSPI/KOSDAQ 자체 지수, 외국인/기관/개인 수급, 업종·종목 리더십), PAGE 2/2(정책 카드 비교 — 미국 정책 4개 vs 한국 정책 4개, 각 카드 사실상태/향후방향/한국시장영향/Polarity/정확도, 미·한 연결경로 4개, 다음 실행 전 체크포인트 8개, 변화추적 기준선 A/B/C/D).
- 같은 날짜에 **오전판/정오판/마감판**이 각각 존재 — 세션별 반복 생성으로 추정(확인된 KPI 세트가 오전/정오/마감마다 조금씩 다름: 마감판엔 삼성전자·SK하이닉스 개별종목, 수급 상세가 추가됨).

## 착수 전 확인해야 할 핵심 질문

1. **데이터 소스**: KOSPI/KOSDAQ 지수·외국인/기관/개인 수급 데이터를 어디서 가져올까? (yfinance는 KOSPI 지수는 되지만 수급 데이터는 지원 안 함 — KRX 정보데이터시스템 스크레이핑? 유료 API? 수기 입력?)
2. **정책 카드 비교(PAGE 2)의 정책 8개**는 뉴스에서 자동 추출 불가능한 수준의 정성 판단(Polarity·정확도 평가 포함) — Family A처럼 룰 템플릿으로 될지, 아니면 사용자가 주기적으로 수기 갱신하는 정책 JSON(`econ_calendar.json`과 유사 패턴)이 될지?
3. **세션 트리거**: 오전/정오/마감 3번을 정말 다 만들지, 아니면 1개(예: 마감판)만 우선 만들지? 3개라면 온디맨드 버튼을 세션마다 누르는 방식인지, 스케줄 자동화가 필요한지(Family A는 온디맨드로 확정했었음).

## 데이터 소스 후보(2026-08-17 추가)

외국인/기관/개인 수급 데이터는 yfinance로 불가 — 사용자가 키움증권 API(가급적 REST API, 구 OCX Open API+는 Streamlit 통합 어려움) 전환을 제안. [[project-daily-market-dashboard]] Family D 백로그에도 동일 메모. 착수 시 브레인스토밍에서 정식 검토.
