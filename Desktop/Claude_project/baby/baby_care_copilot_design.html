BabyCue — 멀티모달 육아 케어 코파일럿

아기의 울음(음성)·표정/상태(이미지)·상황(텍스트)을 함께 보고, "무엇이 문제인지"를 단정하는 번역기가 아니라 "지금 무엇을 해보면 좋을지"를 안내하는 의사결정 보조 도구. 불확실성을 솔직하게 드러내고, 위험 신호는 병원으로 에스컬레이션합니다.

결론부터: 수요는 분명히 존재하지만, "울음 번역기" 카테고리는 이미 포화 + 신뢰도 논란이 큽니다. 데이터로 정리합니다.

3→3한 울음 세션에 3번 분석 → 3개 상이한 진단 (사용자 불만)

🟢 수요를 뒷받침하는 신호

  • 육아앱 시장 고성장 (CAGR 12~20% 추정).
  • 새내기 부모 불안 만연(88.5%) → "지금 뭘 해야 하지?" 의사결정 지원 니즈 큼.
  • Nanni(50만+ 부모), 크라잉베베, CryBaby, ChatterBaby 등 사용자 기반 형성됨 = 시장 검증 완료.
  • 부모가 가치 있게 보는 기능: 배우자/가족 데이터 동기화, 커뮤니티, 구체적 가이드.

🔴 경쟁 카테고리의 약점 (= 우리의 기회)

  • 대부분 오디오 단일 모달 → 같은 울음에 매번 다른 결과(신뢰 붕괴).
  • 연구자들이 "가짜 cry tech 박물관"을 운영할 만큼 과장 정확도 비판.
  • 한 DB의 'gassy' 라벨이 실제론 성인 목소리였던 사례 → 데이터 품질 문제.
  • "무엇을 원하는지" 단정만 하고 구체적 행동 가이드·위험 에스컬레이션 부재.

📌 종합 판단

제품을 폐기할 필요는 없다. 다만 require.txt의 원안에 이미 들어있던 두 가지 직관 — ①멀티모달(음성·이미지·텍스트), ②"틀릴 수 있으니 가이드/행동 지침을 함께 제공" — 이 정확히 경쟁군의 빈틈이다. 따라서 방향을 크게 틀기보다, "울음 번역기"라는 포지셔닝만 폐기하고 "불확실성을 인정하는 멀티모달 케어 코파일럿"으로 재포지셔닝하는 것을 권고한다.

2 제품 컨셉 & MVP 범위

"한 화면에서 입력 → 가능성 순위 → 행동 가이드 → 결과 피드백"의 단일 루프에 집중.

🎙️ 멀티모달 입력

10초 울음 녹음 + (선택) 아기 사진/짧은 영상 + 자유 텍스트("2시간 전 수유함") + 환경값(온·습도).

🧠 추론 & 랭킹

배고픔/기저귀/졸림/트림·복통/덥거나 추움/불편함/아픔 등 후보를 확률 순위 + 근거로 제시.

✅ 행동 가이드

1순위 원인에 대한 구체적 단계 + "안 되면 다음으로" 분기 + 위험 신호 시 병원 안내.

⚠️ 안전·법적 포지셔닝(필수): 의료기기/진단 도구가 아닌 정보·보조 도구로 명확히 고지. 발열, 호흡곤란, 청색증, 무반응, 지속적 고음 울음 등은 추론을 건너뛰고 즉시 의료 도움 안내로 직행한다.

4 프로그램 설계 — 런타임 플로우

한 번의 "아기가 울어요" 이벤트가 처리되는 경로.

  1. 입력 수집: 사용자가 녹음 시작 → 10초 오디오 + (선택)사진/텍스트 + 자동 첨부되는 최근 로그(마지막 수유·수면·기저귀 시각).
  2. 안전 게이트 우선 평가: 텍스트/체크박스로 위험 신호(발열·호흡곤란 등) 입력 시 즉시 병원 안내 화면으로 분기, 추론 생략.
  3. 전처리: 울음 구간 검출(VAD)·노이즈 제거, 이미지 정규화.
  4. 모달별 추론: Audio/Vision 모델이 각각 원인 후보에 점수 부여.
  5. 컨텍스트 융합: 모델 점수 + 로그 규칙(예: "마지막 수유 3시간 전"→배고픔 가중) 결합 → 후보 재정렬.
  6. 설명·가이드 생성: LLM이 상위 후보의 근거 + 단계별 행동 가이드 + "안 되면 다음 시도"를 자연어로 생성(KB 가이드 grounding).
  7. 결과 제시: 확률 순위(예: 배고픔 62% · 졸림 21% · 불편 12%) + 1순위 가이드 + 불확실성 고지.
  8. 피드백 루프: "이게 맞았나요? / 무엇이 효과 있었나요?" 수집 → 개인화 + 모델 재학습 데이터.

5 UX 화면 흐름 (MVP)

① 홈 / 녹음

큰 "🎙️ 듣기 시작" 버튼. 아래 작은 칩으로 사진/메모 추가. 최근 로그 자동 표시.

② 분석 결과

확률 막대 순위 + 1순위 근거. "왜 이렇게 봤나요?" 펼치기. 불확실성 배너.

③ 행동 가이드

단계 체크리스트 + "효과 없었어요 → 다음 시도". 위험신호면 빨간 병원 카드.

④ 피드백

"맞았나요?" 한 번 탭. 무엇이 효과 있었는지 기록.

⑤ 타임라인

수유·수면·기저귀·울음 에피소드 통합 로그. 가족 공유.

⑥ 가족 공유

배우자 초대, 동일 아기 데이터 동기화(부모가 원하는 기능).

7 단계별 로드맵

Phase 0 · 검증 (2~3주)

랜딩페이지 + 부모 인터뷰 20명. "확률+가이드+안전" 컨셉에 대한 지불의사 확인.

Phase 1 · Thin MVP (4~6주)

오디오+텍스트+로그 → 규칙/LLM 융합 가이드. Vision·온디바이스·센서 제외. 핵심 루프 한 화면.

Phase 2 · 신뢰 강화

피드백 기반 개인화, 오디오 분류 모델 고도화, 안전 게이트 전문가 검수.

Phase 3 · 멀티모달 확장

Vision(표정/홍조), BLE 온습도, 가족 공유·타임라인.

Phase 4 · 생태계

커뮤니티, 소아과 연계, 웨어러블 연동.

8 만약 이 방향도 약하다면 — 인접 대안

리서치상 본 제품의 수요는 충분하다고 보지만, 차별화가 어려울 경우의 인접 피벗 후보.

A. 야간 수면 코파일럿

"왜 안 자는가"에 특화 — 수면 회귀·연관성 분석 + 야간 행동 가이드. 통점이 가장 날카로운 시간대 공략.

B. 가족 케어 OS

분석보다 다중 양육자 동기화·인계 중심(부모가 명시적으로 원한 기능). 분석은 부가.

C. 증상 트리아지

발진/대변/체온 사진·로그 기반 "병원 가야 하나?" 판단 보조. 안전 가치가 분명, 신뢰 확보 용이.
