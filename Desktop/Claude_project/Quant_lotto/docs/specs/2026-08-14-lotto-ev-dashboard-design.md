## 배경과 원칙 (스파이크 판정)

전 회차(1~1,236회, 2002-12-07 ~ 2026-08-08) 백테스트 결과:

1. **예측력 없음**: 번호 출현빈도는 균등 랜덤과 구분 불가 (카이제곱 p=0.957).
   핫넘버/콜드넘버/장기미출현/종합점수 전략 모두 랜덤(0.800개 적중)과 통계적으로 동일.
2. **"직전 회차 번호는 연속으로 안 나온다"는 거짓**: 61.3% 회차에서 1개 이상 재출현 (평균 0.825개, 이론값 0.80).
3. **EV(당첨금 독식) 각도는 유효하나 효과 소폭**: 생일조합 회차 1등 당첨자 1.07배 vs 비생일조합 0.95배 (~12%).
   유일한 유의 신호: 연속수 포함 조합은 당첨자 수가 유의하게 적음 (Spearman rho=-0.089, p=0.004).

**설계 원칙**: 조합 생성은 균등 랜덤 기반. 과거 데이터는 ① 참고용 통계 표시 ② EV 최적화에만 사용.
모든 빈도 통계에 "참고용 — 예측력 없음(백테스트 검증됨)" 라벨 고정.

## 2. 데이터 계층 (lotto_data.py)

- 소스: GitHub `smok95/lotto` 회차별 JSON (동행복권 공식 API는 봇 차단 확인됨)
- 첫 실행: 전 회차 다운로드 → `data\history.csv`. 이후: 캐시 마지막 회차+1부터 404까지 증분 요청
- 컬럼: round, date, n1..n6(정렬), bonus, first_winners, first_prize, total_sales

## 3. 화면 구성 (3탭)

- **탭① 통계 대시보드**: 번호별 출현빈도 차트(기대값 기준선), 최근 N회 핫/콜드 top10,
  랜덤성 모니터(카이제곱 p값 + 문구, 직전회차 겹침 실측), 참고용 라벨 고정
- **탭② EV 조합 생성기**: 1~5게임 생성(균등 랜덤 + EV 필터), 조합별 독식 점수(0~100)와 근거 표시
- **탭③ 내 조합 검증기**: 6개 번호 입력 → 과거 전 회차 등수 히스토리, 독식 점수,
  당첨 확률 정직 표기(1/8,145,060 — 모든 조합 동일)

## 4. EV 독식 점수 (0~100)

스파이크에서 확인된 신호만 반영. "당첨 확률과 무관 — 당첨 시 분할 리스크만 반영" 문구 필수.

- 연속수 포함: +30 (유일한 유의 신호)
- 31 이하(생일범위) 비중 낮음: 최대 +30
- 40번대 포함: +20
- 번호 합계가 인기 구간(100~170) 밖: +20

## 5. 에러 처리 · 테스트

- GitHub 접속 실패: 캐시 있으면 "N회차 기준" 경고 후 동작, 없으면 안내 후 중단
- 검증기 입력: 중복/범위(1~45) 검사
- pytest: 등수 판정(1~5등·보너스), EV 점수 경계값, 증분 업데이트 병합
